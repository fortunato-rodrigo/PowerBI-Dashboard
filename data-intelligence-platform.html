02 — Arquitetura

As camadas de dados

Cada camada tem uma responsabilidade clara. Dados sobem em qualidade da RAW até o Power BI, enquanto metadados e documentação fluem para a camada de inteligência.

Camada 0
RAW / BRONZE
Databricks · AWS S3

Dados brutos ingeridos diretamente das fontes — sistemas transacionais, APIs externas, arquivos e eventos. Nenhuma transformação é aplicada. O objetivo é preservar a fidelidade total dos dados originais para rastreabilidade e reprocessamento.

Dados sem transformação Ingestão em batch e streaming Auditoria e reprocessamento Metadados fracos
↓
Camada 1
SILVER
DBT · Databricks

Dados limpos e padronizados. O DBT aplica regras de qualidade, normaliza tipos, remove duplicatas e documenta cada modelo via arquivos YML. Cada tabela Silver possui descrição do modelo e descrição de cada coluna — essa documentação é a base da nossa ontologia.

YML documentado no DBT Descrição de colunas Dados limpos e tipados Testes de qualidade Joins e relacionamentos
↓
Camada 2
GOLD
DBT · Databricks

Tabelas analíticas prontas para consumo. Agregações, métricas de negócio pré-calculadas, modelos dimensionais (fatos e dimensões). É aqui que a linguagem técnica começa a se traduzir em linguagem de negócio — net_revenue se torna Receita Líquida.

Métricas pré-calculadas Modelo dimensional YML documentado no DBT Fatos e dimensões Alta qualidade de dado
↓
Camada 3
Power BI
PBIP · Semantic Model · DAX

30+ dashboards conectados às camadas Databricks. O formato PBIP (Power BI Project) salva todas as medidas DAX, relacionamentos e estrutura de relatório como arquivos de texto — legíveis por humanos e pela IA. Cada dashboard terá documentação gerada automaticamente via Claude Code.

Formato PBIP (texto legível) Medidas DAX documentadas Semantic Model README por dashboard Conecta em Bronze/Silver/Gold
↓
Camada 4
Inteligência
Claude AI · GitHub · Ontologia

A camada que une tudo. A Claude carrega o contexto completo — ontologia corporativa, documentação de todos os dashboards, metadados DBT — e responde perguntas em linguagem natural. Via MCP, consulta o Databricks em tempo real para dados atualizados.

Respostas em linguagem natural MCP Databricks em tempo real Ontologia corporativa Rastreabilidade completa Sem licença adicional
03 — Ontologia

A ontologia corporativa de dados

Um conjunto de quatro documentos vivos que traduzem a linguagem técnica dos dados para a linguagem do negócio — e garantem que "receita" significa a mesma coisa em todos os dashboards da empresa.

GLOSSARY.md
Glossário Corporativo

O dicionário canônico da empresa. Cada termo de negócio tem uma única definição, aprovada e sem ambiguidade. Se dois dashboards calculam "churn" de formas diferentes, isso aparece aqui como conflito explícito — e resolve a disputa de forma definitiva.

## Churn Rate
Definição: percentual de clientes que cancelaram
no período em relação à base do início do período.
Fórmula: cancelamentos / base_inicio * 100
Owner: Customer Success
Fonte: gold_subscriptions.churn_flag
KPIS.md
KPIs Estratégicos

Os indicadores que o board e os líderes acompanham, com contexto completo: fórmula de negócio, meta vigente, frequência de monitoramento, owner e qual dashboard é a fonte autoritativa. A Claude usa isso para contextualizar qualquer análise.

## GMV (Gross Merchandise Value)
Descrição: volume total transacionado
Meta 2025: R$ 500M
Frequência: diária
Owner: Finanças — CFO
Dashboard: /dashboards/Financeiro/
DOMAINS.md
Domínios de Negócio

Mapa de responsabilidades: qual área é dona de quais dados e dashboards. Vendas é responsável por fact_orders. CS é responsável por dim_customers. Isso resolve conflitos de ownership e direciona perguntas ao stakeholder correto.

## Domínio: Vendas
Owner: VP de Vendas
Tabelas: fact_orders, fact_quotes
Dashboards: Vendas/, Pipeline/
KPIs: Receita, Conversão, CAC
Contato: squad-dados-vendas@empresa
MAPPING.md
Mapeamento Semântico

A cola entre todas as camadas. Traduz explicitamente como um termo de negócio se conecta a uma medida DAX no Power BI e a uma coluna no Databricks. É o que permite à Claude rastrear de onde vem cada número que aparece em um dashboard.

## Receita Líquida
→ Sinônimos: faturamento, revenue, fat. liq.
→ DAX: [Faturamento Líquido]
   no modelo Vendas.SemanticModel
→ Databricks: gold_orders.net_revenue
→ DBT model: gold_orders.yml (documentado)
O DBT já fez metade do trabalho

Os arquivos YML do DBT já documentam cada tabela Silver e Gold com descrições de modelos e colunas. Um script extrai automaticamente esses metadados e os incorpora ao MAPPING.md. A ontologia não começa do zero — herda o trabalho já feito pelo time de dados.

Construção incremental

A ontologia não precisa estar completa para ser útil. Começa com os 20 termos mais confusos e os 10 KPIs mais perguntados. Cada novo dashboard documentado sugere automaticamente adições ao glossário. O repositório cresce sozinho.

04 — Repositório

Estrutura do repositório GitHub

Todo o conhecimento de dados da empresa vive em um único repositório versionado. Cada mudança é rastreável, cada novo dashboard passa por um Pull Request com documentação incluída.

📁 PowerBI-Dashboard/ # repositório GitHub corporativo
 
├── CLAUDE.md # instruções globais — lidas automaticamente pelo Claude Code
 
├── ontologia/ # camada semântica corporativa — transversal a todos os dashboards
│ ├── GLOSSARY.md # termos canônicos da empresa
│ ├── KPIS.md # KPIs estratégicos com owner e meta
│ ├── DOMAINS.md # domínios de negócio e responsabilidades
│ └── MAPPING.md # termo negócio → DAX → coluna Databricks
 
├── dbt-metadata/ # extraído automaticamente dos YML do DBT
│ ├── silver_models.md # gerado por script — tabelas Silver documentadas
│ └── gold_models.md # gerado por script — tabelas Gold documentadas
 
├── .claude/skills/ # instruções automáticas para o Claude Code

05 — Valor

O que a empresa ganha

Uma infraestrutura de conhecimento que cresce com o negócio e democratiza o acesso aos dados.

🔍
Rastreabilidade total

Qualquer número em qualquer dashboard tem sua origem rastreável até a tabela Databricks — passando pelo modelo DBT e pela medida DAX.

💬
Perguntas em linguagem natural

Qualquer colaborador pode perguntar "qual dashboard mostra o churn por segmento?" ou "de onde vem o dado de receita?" sem depender do time de BI.

📚
Documentação sempre atualizada

Cada Pull Request de novo dashboard inclui a documentação gerada automaticamente. O conhecimento não fica na cabeça das pessoas.

🤝
Uma verdade única

O GLOSSARY.md elimina discussões sobre o que "churn" ou "receita" significa. Um termo, uma definição, aprovada pela área responsável.

⚡
Velocidade de onboarding

Novos analistas e gestores entendem o ecossistema de dados em dias, não meses. A ontologia é o mapa que faltava.

💰
Sem custo adicional

Funciona com a licença Power BI Pro existente. O repositório é GitHub. A IA é Claude. Nenhuma nova licença de plataforma é necessária.
